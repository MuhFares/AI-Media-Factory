## Purpose and boundary

This program converts the canonical OpenRouter catalog and actual registered AMF roster into a reproducible, role-specific benchmark and proposed-routing architecture. It does not infer, benchmark, spend, activate routing, produce content, or grant authority.

## Canonical funnel

`full provider catalog → declared-capability compatibility → role candidate pool → versioned benchmark → finalists → proposed routing → explicit Owner activation`

Provider metadata establishes eligibility only. It is not AMF quality evidence. UNKNOWN remains UNKNOWN. Deterministic and provider-specific runtime agents are mapped but are not forced into an OpenRouter text-model pool.

## Agent/task profiling

All 24 registered entries in `apps/api/src/agent-catalog.ts` are mapped to reasoning, creativity, structure, tools, context, vision, latency, frequency, cost, reliability, and factuality requirements. CEO is executive synthesis. Orchestrator is a separate execution-control class emphasizing tools, structure, state, failure handling, and authority compliance. Media transports and authorization gates remain deterministic/provider-specific where the runtime says so.

## Company Brain

The executive chain is: Evidence/Memory → Analytics → Specialist Agents → Executive Synthesis → CEO Reasoning → Owner Boundary. CEO output is recommendation-only. Its PRIMARY, FALLBACK, ECONOMY, and PREMIUM_ESCALATION slots remain unassigned pending benchmark evidence. Escalation is controlled and cannot grant spend, production, or publication authority.

## Dataset and evaluation

Dataset `AMF-MRB-V1.0.0` covers research, strategy, planning, brief, script, hooks, scenes, visual prompts, metadata, critic, QA, analytics, CEO executive reasoning, and Orchestrator control. Identical inputs are required within each role comparison. Raw dimensions remain separate: quality, reasoning, factuality, creativity, instruction adherence, structured output, tool reliability, context, multimodal handling, latency, tokens, estimated/calculable/billed cost, errors, retries, and consistency.

Creative tasks support anonymous Candidate A/B/C review; model identity is retained internally and revealed only after independent Owner judgment.
